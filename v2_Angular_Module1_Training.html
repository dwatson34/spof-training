Concept 1

Angular Architecture

How Angular applications are structured and compiled

Angular is a platform for building single-page applications. Understanding its architecture helps you navigate the Xuber codebase and diagnose problems in the right layer.

Core building blocks

NgModules

Application containers

NgModules group related components, directives and pipes. Every Angular app has a root AppModule. Feature modules group related functionality.

Components

UI building blocks

Every visible part of the UI is a component: a TypeScript class with a template and metadata. Components are the primary units of code you will work with.

Services

Business logic and data

Services contain logic that is not UI-specific. HTTP calls, state management, utilities. Shared across components via dependency injection.

Directives

Template behaviour

ngIf, ngFor, ngClass. Structural directives change the DOM structure. Attribute directives change element appearance or behaviour.

Xuber app structureStructure
src/app/
  core/           // singletons: auth, guards
  shared/         // reusable components
  features/
    policy/       // policy feature module
      components/
      services/
        policy-api.service.ts
        policy-facade.service.ts
      models/
        policy.model.ts
      policy.module.ts
      policy-routing.module.ts
    claims/       // claims feature module
  app.module.ts
  app-routing.module.ts
Feature modules: Each business domain (policy, claims, LMM) is a separate Angular feature module. They are lazy-loaded - only downloaded when the user navigates to that area.

Concept 2

Components

Templates, component class, metadata and the component lifecycle

Components are the most important concept in Angular. Every visible part of the Xuber HTMLUI is a component. Understanding how they work is essential for reading and writing Xuber code.

policy-list.component.tsTypeScript
@Component({
  selector:    'app-policy-list',
  templateUrl: './policy-list.html',
  styleUrls:  ['./policy-list.scss']
})
export class PolicyListComponent
    implements OnInit {

  // Input from parent component
  @Input() pageSize = 25;

  // Output event to parent
  @Output() policySelected =
    new EventEmitter<Policy>();

  policies$ = this.facade
    .getPolicies();

  constructor(
    private facade:
      PolicyFacadeService
  ) {}

  ngOnInit() {
    // Runs once after init
  }
}

Lifecycle hooks

ngOnInit

After first change detection

Safe place to load data. Input properties are available here. Avoid heavy logic in the constructor.

ngOnChanges

When Inputs change

Called before ngOnInit and every time an Input property changes. Receives a SimpleChanges object.

ngOnDestroy

Before component removed

Unsubscribe from Observables here. Clear timers. Call destroy on subjects. Prevents memory leaks.

Async pipe: Use the async pipe in templates instead of subscribing in the component class. It automatically unsubscribes when the component is destroyed.

Concept 3

Data Binding

Interpolation, property binding, event binding and two-way binding

Data binding connects your component class to its template. Angular has four binding types. Understanding each prevents common bugs in the Xuber HTMLUI templates.

Interpolation

{{ value }}

Renders a component property as text. Use for displaying data: {{ policy.ref }} or {{ policy.premium | currency }}

Property Binding

[property]="value"

Sets an element or component property from a class value. [disabled]="isLoading" sets the disabled attribute dynamically.

Event Binding

(event)="handler()"

Responds to DOM events. (click)="onSave()" calls the component method when the button is clicked. ($event) passes the event object.

Two-way Binding

[(ngModel)]="value"

Combines property and event binding for form inputs. Requires FormsModule. Synchronises input value with component property in both directions.

policy-list.component.html - all four typesHTML
<!-- Interpolation -->
<h2>{{ policies.length }} policies</h2>

<!-- Property binding -->
<button [disabled]="isLoading">Refresh</button>

<!-- Event binding -->
<button (click)="loadPolicies()">Load</button>

<!-- Two-way binding -->
<input [(ngModel)]="searchTerm">

<!-- Async pipe - auto-unsubscribes -->
<div *ngFor="let p of policies$ | async">
  {{ p.ref }}
</div>

Concept 4

Services and Dependency Injection

Creating injectable services and understanding the Angular DI system

Services contain business logic and data access. The dependency injection system creates service instances and makes them available to components. In Xuber, every API call goes through a service - never directly from a component.

policy-facade.service.tsTypeScript
@Injectable({
  // Singleton - shared across app
  providedIn: 'root'
})
export class
    PolicyFacadeService {

  constructor(
    private api:
      PolicyApiService
  ) {}

  getPolicies(
    params: PolicyListParams
  ): Observable<Policy[]> {
    return this.api
      .getList(params)
      .pipe(
        map(r => r.data),
        catchError(
          () => of([])
        )
      );
  }
}
providedIn: root

Application singleton

One instance shared across the entire application. Use for services that hold state or make HTTP calls.

Constructor injection

Declare in constructor

Services are injected via the constructor. Angular's DI creates the instance automatically. Never use new ServiceName() directly.

Tree-shakeable

Only included if used

providedIn: root makes the service tree-shakeable - if no component injects it, it is not included in the bundle.

Xuber service pattern: PolicyApiService handles raw HTTP. PolicyFacadeService orchestrates and transforms. Components only inject the Facade. This is the two-service rule from the API module.

Router and HttpClient

Navigation, route guards, lazy loading, and making HTTP calls with RxJS

The Angular Router handles navigation between pages without page reloads. HttpClient makes HTTP calls and returns Observables. Together they power all of Xuber's data loading and navigation.

Router essentials

app-routing.module.tsTypeScript
const routes: Routes = [
  { path: '',
    redirectTo: 'policies' },
  { path: 'policies',
    // Lazy loaded module
    loadChildren: () =>
      import('./features/policy/
        policy.module')
      .then(m =>
        m.PolicyModule),
    canActivate: [AuthGuard]
  },
  { path: 'claims/:id',
    component:
      ClaimDetailComponent
  },
  { path: '**',
    redirectTo: 'policies' }
];

Key RxJS operators for Xuber

map

Transform data

map(response => response.data) - extract the data array from a paginated response.

catchError

Handle errors

catchError(err => of([])) - return an empty array instead of crashing when an API call fails.

switchMap

Cancel previous calls

switchMap(filters => api.getList(filters)) - cancels the previous HTTP call when filters change. Prevents stale data.

debounceTime

Throttle events

debounceTime(300) on a search input - waits 300ms after the user stops typing before making an API call.

async pipe: Use the async pipe in templates rather than subscribe() in the component. It handles unsubscription automatically and prevents memory leaks.
