XuWebApiManager Internals

Click each tab to understand how the real source code works under the hood.

At Beginner level you learned what XuWebApiManager does. Now you will see exactly how it does it by reading the real xuWebApiManager.service.ts source file.

get() method — real sourceTypeScript
import { lastValueFrom } from 'rxjs';

get(url, getParameters?, errorHandler?) {
  var self = this;
  url = this.CorrectUrl(url);
  // ... build fullUrl with params ...
  return lastValueFrom(
    this.http.get(fullUrl)
  )
    .then(response => response)
    .catch(error =>
      this.handleError(
        error, self, errorHandler
      )
    );
}

Why lastValueFrom()?

Angular’s HttpClient.get() returns an Observable<T>. But Xuber’s entire codebase uses Promises. lastValueFrom() from RxJS bridges the gap — it subscribes to the Observable, waits for it to complete, and resolves a Promise with the last emitted value. This is how Xuber converts Observable to Promise throughout the codebase.
toPromise() was deprecated in RxJS 7. lastValueFrom() is the modern replacement. The XuberHTML codebase was updated to use lastValueFrom when Angular and RxJS were upgraded. If you see toPromise() in older code, it is the same concept but the deprecated version.
CorrectUrl() — real sourceTypeScript
private CorrectUrl(url: string) {
  if (url.startsWith('api/')) {
    return '/XuberHTMLApi/' + url;
  }
  else {
    return url;
  }
}

// Example:
// 'api/claims/getClaimsPreviewData'
// becomes:
// '/XuberHTMLApi/api/claims/
//   getClaimsPreviewData'

Why this matters for debugging

This is why every Xuber API call appears in the Network tab as /XuberHTMLApi/api/... even though the service files just say api/.... CorrectUrl() is called on every request before it is sent. If a URL does NOT start with api/ it is passed through unchanged — used for the token refresh call to /XuberHTMLApi/api/task/GetToken.
Query string building — real sourceTypeScript
if (_.isEmpty(getParameters)) {
  fullUrl = url; // no params
} else {
  // handle Date objects first:
  for (var key in getParameters) {
    if (getParameters[key]
      instanceof Date) {
      getParameters[key] =
        window.xuMoment(
          getParameters[key]
        ).xuFormat();
    }
  }
  // jQuery serialise to query string:
  let paramString =
    $.param(getParameters);
  fullUrl += '?' + paramString;
}

How params become a query string

$.param() is jQuery’s parameter serialiser. It converts the params object into a URL query string: {"{claimReference:'XUK001',eventId:42}"} becomes claimReference=XUK001&eventId=42. This is why Xuber has jQuery as a dependency even though it is primarily an Angular app — it uses jQuery for query string serialisation.
_ is Lodash, another Xuber dependency. _.isEmpty(getParameters) returns true if the params are undefined, null, or an empty object. This allows calling xuWebApiManager.get(url) with no params for endpoints that don’t need any — like getAddAmountGroupsFilterRows().

The custom xuMoment wrapper

window.xuMoment is a custom Xuber wrapper around the Moment.js library. .xuFormat() serialises dates to the format the XuberHTMLApi .NET backend expects. This is automatic — any Date object in the params is converted before the query string is built. You never need to format dates manually when calling a service method.
getDownload() — returns ObservableTypeScript
getDownload(url, getParameters?):
  Observable<any> {
  // builds fullUrl same as get()...
  return this.http.get(fullUrl, {
    responseType: 'arraybuffer',
    observe: 'response'
  }).pipe(
    map(response => response)
  );
}
// NOTE: getDownload returns Observable
// NOT Promise. Use .subscribe() here.
// This is the ONE exception to the
// Promise-everywhere rule.

The Observable exception

⚠️
Critical distinction

getDownload() is the only method in XuWebApiManager that returns an Observable instead of a Promise. It uses responseType: arraybuffer for binary file downloads and observe: response to access HTTP response headers (needed for filename etc). When consuming getDownload(), use .subscribe() not .then().

Pattern 1: Simple GET — single required param

Example: startUWNotesTransaction(reference: string) → api/underwriting/StartUWNotesTransaction
When to use: One reference or ID identifies the resource completely. No optional context needed.
Pattern: private static path → var params = {reference: reference} → xuWebApiManager.get(url, params).then(r => {log; return r;})

The Xuber service template

Copy this template for any new Xuber service methodTypeScript
private static myNewEndpointApiPath = 'api/domain/MyNewEndpoint';

myNewEndpoint(requiredParam: string, optionalParam?: number) {
  var params = {
    requiredParam: requiredParam,
    optionalParam: optionalParam   // undefined if not provided = omitted from query string
  };
  let url = MyService.myNewEndpointApiPath;
  return this.xuWebApiManager
    .get(url, params)              // or .post() if sending array in body
    .then(response => {
      this.xuLoggerService.debugResponse(url);
      return response;
    });
}
Pattern Recognition Challenge
You need to add a method that sends a list of policy references to bulk-cancel them. Which pattern should you use and why?
✅ Correct! Arrays must be sent in a request body rather than a query string. Use xuWebApiManager.post(url, params). The only difference from a GET method is .post() instead of .get() — the params object, static path constant and .then() chain are identical.

Error Handling in XuWebApiManager

Click ▶ to step through what happens when an API call fails. Understanding this is essential for diagnosing production issues.

When an API call fails, handleError() in XuWebApiManager processes the HttpErrorResponse. Understanding this function tells you exactly what information is available when things go wrong.

The error handling flow — click ▶ to step through

Click to step through
1

HTTP error response received

The .catch() in get() or post() fires and calls handleError(error, self, errorHandler). The error is an HttpErrorResponse.

2

Check Content-Type header

If the response is application/json, the body is parsed. body.errors[0].message becomes the errMsg. The full error object is stored in retVal['errorObject'].

3

Non-JSON: check status code

If the response is not JSON and the status is 401, errMsg is set to "Token timeout, please refresh." This is the specific 401 message users see.

4

Token auto-refresh check

If errMsg matches Xuber.error.token.message, XuWebApiManager automatically calls /XuberHTMLApi/api/task/GetToken?resetToken=true and sets the response as a cookie. This refreshes the session silently.

5

Custom errorHandler or reject

If the service method passed a custom errorHandler function, it is called with the error. Otherwise Promise.reject(retVal) is returned — the caller receives an object with errorMsg and errorObject.

6

The retVal object in the component

The component’s .catch() or rejected Promise receives: retVal.errorMsg (human readable string) and retVal.errorObject (full API error JSON). Always check both when diagnosing.

handleError() — real source (condensed)TypeScript
private handleError(
  error: HttpErrorResponse,
  webApiManager: XuWebApiManager,
  errorHandler?: (any) => Promise<any>
): Promise<any> {
  let retVal = {};
  const contentType =
    error.headers.get("content-type");

  if (contentType?.includes(
    "application/json")) {
    const body = error.error || '';
    retVal['errorObject'] = body.error;
    if (body.errors?.length > 0) {
      errMsg = body.errors[0].message;
    }
  } else if (error.status == 401) {
    errMsg = "Token timeout, please refresh.";
  }

  if (errMsg == Xuber.error.token.message) {
    webApiManager.get(
      '/XuberHTMLApi/api/task/GetToken',
      { resetToken: true }
    ).then(r => {
      webApiManager.doc.cookie = r;
    });
  }
  return Promise.reject(retVal);
}

What to check when an error reaches a component

This is the string from body.errors[0].message in the JSON response, or the HTTP status text for non-JSON errors. This is what you log and potentially show to users. Check this first when a service call fails.
This is the full parsed JSON body from the API error response. It contains validation details, field-level errors and any additional context the backend provided. For complex 400 errors with multiple validation failures, this is where to look.
The auto-refresh only fires if errMsg exactly equals the string defined in Xuber.error.token.message (from xuberConstants.ts). A generic 401 that returns a different error message will NOT trigger the auto-refresh. The user will see an error and need to log in manually.

Scenario Challenges

Intermediate Scenario Challenges

Four situations requiring Intermediate-level knowledge. Think before selecting.

Scenario 1 — XuWebApiManager Internals
A service method passes a JavaScript Date object as a parameter. What happens to it before the HTTP request is sent?
✅ Correct! XuWebApiManager loops through all params and converts any Date instances using the custom window.xuMoment().xuFormat() wrapper. This ensures the .NET API receives dates in the correct format regardless of the browser’s locale.
Scenario 2 — Error Handling
A component calls a service method and it fails. In the .catch() handler, the error object has errorMsg: "Token timeout, please refresh." but the screen did not show an error. Why?
✅ Correct! When errMsg exactly matches Xuber.error.token.message, XuWebApiManager automatically calls the token refresh endpoint and sets the new token as a cookie. This is the silent session refresh mechanism.
Scenario 3 — getDownload()
A new developer sees a component using .subscribe() on a call to xuWebApiManager.getDownload() and says it must be wrong because "Xuber uses Promises not Observables." Are they correct?
✅ Correct! getDownload() is the single exception — it returns an Observable<any> because it needs responseType: arraybuffer and access to the full HTTP response object (including headers for filename extraction). Using .subscribe() is correct and intentional.
Scenario 4 — Underwriting Quirks
You are reviewing a PR that fixes the typo in UpdateManuaPremiumAmountChange by updating the static path constant in XuUnderwritingService. Should you approve it?
✅ Correct! This is a known codebase quirk. The typo exists in both the Angular private static path constant AND the .NET API controller route. Changing only one side breaks the endpoint. Reject the PR and require a coordinated frontend + backend release.
