Unit Testing with Jasmine

describe, it, expect, beforeEach — the structure of every Angular test file

Jasmine is the test framework; Karma runs tests in a real browser. Every .spec.ts file uses this stack.

policy.service.spec.tsTypeScript
describe('PolicyService', () => {
  let service: PolicyService;

  beforeEach(() => {
    TestBed.configureTestingModule({
      imports: [HttpClientTestingModule]
    });
    service = TestBed.inject(
      PolicyService
    );
  });

  it('should be created', () => {
    expect(service).toBeTruthy();
  });
});

Key concepts

describe()

Test suite

Groups related tests. Nest for sub-features.

beforeEach()

Setup hook

Runs before every it(). Configure TestBed and create spies here.

it()

Single test

Assert exactly one behaviour. Name it clearly.

expect()

Assertion

Matchers: toBe, toEqual, toHaveBeenCalledWith, toThrow.

TestBed & Component Testing

Shallow-render components and assert on their DOM output

TestBed compiles a component with a minimal NgModule so you can render, interact, and assert without a full app.

policy-list.component.spec.tsTypeScript
TestBed.configureTestingModule({
  declarations: [PolicyListComponent],
  providers: [{
    provide: PolicyService,
    useValue: {
      getPolicies: () => of([mockPolicy])
    }
  }]
});
const fixture = TestBed
  .createComponent(PolicyListComponent);
fixture.detectChanges();
const rows = fixture.nativeElement
  .querySelectorAll('tr.policy-row');
expect(rows.length).toBe(1);

Key TestBed APIs

detectChanges()

Trigger rendering

Call after setting inputs or async operations. Angular won't update the DOM until you call it.

useValue stub

Replace services

Provide lightweight objects: { getPolicies: () => of([]) }. Keeps tests fast and isolated.

nativeElement

DOM access

Use querySelector to assert on rendered HTML output.

debugElement

Angular-aware queries

Use .query(By.css()) for Angular-aware element selection.

Testing HTTP Services

HttpClientTestingModule and HttpTestingController

Never make real HTTP calls in tests. HttpClientTestingModule replaces HttpClient with a mock for controlled, verifiable responses.

policy-api.service.spec.tsTypeScript
beforeEach(() => {
  TestBed.configureTestingModule({
    imports: [HttpClientTestingModule]
  });
  httpMock = TestBed
    .inject(HttpTestingController);
});
it('should fetch policies', () => {
  service.getPolicies().subscribe(p => {
    expect(p.length).toBe(2);
  });
  const req = httpMock
    .expectOne('/api/v2/policies');
  expect(req.request.method).toBe('GET');
  req.flush([mockPolicy1, mockPolicy2]);
  httpMock.verify(); // no extra requests
});
expectOne(url)

Assert the call

Fails if 0 or 2+ requests were made to that URL.

req.flush()

Deliver response

Triggers the Observable. Pass {status:500} to simulate errors.

httpMock.verify()

No unexpected calls

Fails if any requests were made but not expected. Always call in afterEach().

afterEach()

Clean up

Call verify() in afterEach() so every test in the suite is protected.

Angular Testing Library

User-centric tests — find elements by role and label, not CSS selectors

@testing-library/angular encourages testing behaviour from the user's perspective. Tests are resilient to refactoring and surface accessibility gaps.

claim-form.component.spec.tsTypeScript
import { render, screen,
  fireEvent } from
  '@testing-library/angular';
it('submits valid claim',
    async () => {
  await render(ClaimFormComponent);
  fireEvent.input(
    screen.getByLabelText(
      'Claim Reference'),
    { target: { value: 'CLM-001' }}
  );
  fireEvent.click(
    screen.getByRole('button',
      { name: 'Submit Claim' })
  );
  await screen.findByText(
    'Claim submitted'
  );
});

Key queries

getByLabelText()

Find by label

Finds an input by its label. Also verifies form accessibility.

getByRole()

Find by ARIA role

button, heading, textbox. Robust to CSS class renames.

fireEvent

Simulate interaction

fireEvent.click(), fireEvent.input() for user actions.

findByText()

Async assertion

Returns a Promise — waits for text to appear after async operations.

Concept 5

Code Coverage

Measuring and reaching the Xuber 80% threshold

Istanbul tracks which lines, branches, functions, and statements are exercised. Xuber requires 80% across all four before a PR can merge.

Run locallyCLI
ng test --no-watch --code-coverage
# Report: coverage/lcov-report/index.html
Statements

Was this line executed?

Every executable statement must run. Raised by adding basic happy-path tests.

Branches

Was every if/else tested?

The hardest metric. Requires tests for both true and false paths of every conditional.

Functions

Was this function called?

Every method must be called at least once across all tests.

Lines

Physical lines hit

Similar to statements but counts physical lines rather than AST nodes.

angular.json — enforce thresholdJSON
"coverageThreshold": { "global": {
  "statements": 80, "branches": 80,
  "functions":  80, "lines":    80
}}

Azure Pipelines & CI

Reading pipeline YAML and fixing common build failures

The Xuber CI pipeline runs on every push. Knowing the YAML structure lets you add steps, fix jobs, and read logs independently.

azure-pipelines.ymlYAML
trigger: [main, develop]
stages:
  - stage: Build
    jobs:
      - job: BuildApp
        steps:
          - task: NodeTool@0
            inputs:
              versionSpec: '20.x'
          - script: npm ci
          - script: ng build --prod
  - stage: Test
    dependsOn: Build
    jobs:
      - job: UnitTests
        steps:
          - script: |
              ng test --no-watch
                --code-coverage
                --browsers=ChromeHeadless
          - task: PublishTestResults@2
          - task: PublishCodeCoverageResults@1

Common failures

Module not found

Run npm ci locally. Check imports for typos.

NullInjectorError

Add the missing provider to TestBed.configureTestingModule providers.

Coverage gate fails

Find uncovered branches in the HTML report and add targeted tests.

ng lint fails

Run ng lint --fix. Check for unused imports, missing types, explicit any.
