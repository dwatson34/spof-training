Concept 1

What is XLPro Integration?

XLPro Integration is the middleware layer that connects Xuber Enterprise with reinsurance systems, policy administration platforms, and external data providers. It handles message routing, transformation, and guaranteed delivery.

Core Concepts

Message Flow Architecture ▼

XLPro Integration uses a publish-subscribe message pattern:

  • Publishers: Xuber Enterprise publishes policy, claim, and financial events
  • Topics: Messages are organized by type (policy, claim, financial)
  • Subscribers: External systems consume messages from topics they care about
  • Guaranteed Delivery: Failed messages queue automatically for retry
When You Need XLPro Integration ▼

XLPro Integration is required when:

  • Syncing policy data between Xuber and external systems
  • Sharing claim events and updates across platforms
  • Feeding financial data to reinsurance or accounting systems
  • Notifying external systems of policy lifecycle changes
  • Integrating with GLOBAL XLPro for multi-company scenarios

Prerequisites & Environment Setup

Before working with XLPro Integration, your environment must meet specific requirements. This section covers what you need to verify and how to confirm your system is ready.

System Requirements

☕

Java Runtime

Java 11 or later required. Check with: java -version

🗄️

Database

Connection to Xuber Enterprise DB. Verify with: sqlplus

🌐

Network Access

Port 5672 (AMQP) and 15672 (Management) open

🔐

Credentials

RabbitMQ user account with publish/subscribe permissions

Pre-Flight Checklist

How do I check if my environment is ready? ▼

Step 1: Verify Java

$ java -version

Step 2: Test Database Connection

$ sqlplus username@xuber_db

Step 3: Check RabbitMQ Port

$ nc -zv rabbitmq.prod 5672
Connection to rabbitmq.prod 5672 port succeeded

Step 4: Verify XLPro Service

$ curl -u admin:pass http://rabbitmq.prod:15672/api/whoami
{"name":"xlpro-user","tags":"administrator"}

Architecture & Components

XLPro Integration consists of several interconnected components. Understanding how they work together is essential for monitoring, troubleshooting, and scaling.

Key Architecture Components

📨

Message Broker

RabbitMQ or Apache Kafka. Stores messages and guarantees delivery to subscribers.

🔄

Routing Engine

Evaluates rules to determine which queues receive each message type.

🎭

Message Transformer

Converts Xuber format to system-specific formats (JSON, XML, CSV).

⚠️

Dead Letter Queue (DLQ)

Holds failed messages that exceed retry limits for manual review.

// XLPro Integration Architecture
XuberEnterprise
