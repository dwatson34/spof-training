Concept 1

What Is GLOBAL XLPro

Understanding the purpose and role of XLPro in the Xuber ecosystem

GLOBAL XLPro is a ceded reinsurance solution. It provides Xuber Enterprise with integration capabilities to enable seamless data synchronization between Xuber and GLOBAL XLPro systems. The integration ensures that business data created or modified in Xuber Enterprise is reliably transmitted to and processed by GLOBAL XLPro.

XLPro Purpose

Ceded Reinsurance

What It Does

XLPro is a reinsurance platform that handles policies ceded (transferred) from primary insurers. It manages policy data, claims, and financial transactions for reinsured business.

Data Integration

Messaging Hub

XLPro acts as an integration hub, receiving business events from Xuber and synchronizing policy and claims data between systems.

Reliability

Guaranteed Delivery

The integration ensures no data is lost. If the connection fails, messages queue and process when the connection is restored.

In The Xuber Stack

GLOBAL XLPro - Reinsurance Platform
Integration Layer - Data transformation
Xuber Enterprise - Primary system
Xuber Messaging - Event transport
Key Point: When Xuber Enterprise creates a policy or claim, the XLPro integration automatically sends that data to GLOBAL XLPro for processing and synchronization.

When XLPro Integration Is Needed

Scenario 1

Reinsurance Operations

Organizations that broker reinsurance or have reinsured business must integrate Xuber with GLOBAL XLPro to synchronize reinsured policies and claims.

Scenario 2

Multi-System Deployments

When Xuber Enterprise is used alongside GLOBAL XLPro systems, the integration bridges the two platforms and ensures data consistency.

Concept 2

Integration Overview

How XLPro integration works at a high level

The XLPro integration consists of two main installers that work together to synchronize data between Xuber Enterprise and GLOBAL XLPro. The process is automatic and continuous, handling policy events, claims, and financial transactions.

The Two Parts Of XLPro Integration

Part 1

XLPro Integration (Xuber Side)

Installed on Xuber Enterprise and Xuber Messaging servers. Listens for business events in Xuber and sends them to the XLPro database.

Runs on: Xuber Enterprise server, Xuber Messaging server

Part 2

USM 6-9 Load (XLPro Side)

Installed on the GLOBAL XLPro database server. Processes messages from Xuber and loads them into the XLPro database tables.

Runs on: XLPro database server

Data Flow

1. Event Occurs in Xuber Enterprise
2. Xuber Messaging sends event notification
3. XLPro Integration captures and transforms data
4. Data sent to XLPro database staging area
5. USM 6-9 Load processes and loads into XLPro
Message Queuing: If Xuber or the XLPro database is temporarily unavailable, messages queue on the Xuber Messaging server. When the connection is restored, queued messages automatically process in order, ensuring no data loss.

What Gets Synchronized

Data Type

Policy Events

New policies, endorsements, renewals, cancellations - all policy lifecycle events from Xuber flow to XLPro.

Data Type

Claims

Claim creation, reserve changes, claim payments - all claim activity synchronizes to XLPro for tracking.

Data Type

Financial Data

Premiums, payments, financial transactions - accounting data flows to XLPro for financial reconciliation.

Requirements

Integration Prerequisites

What must be in place before deploying XLPro integration

Before you deploy XLPro integration, your environment must meet specific requirements. These prerequisites ensure the integration works reliably and the two systems can communicate securely.

Xuber Enterprise Requirements

Requirement

Xuber Enterprise Deployment

A complete Xuber Enterprise system must be installed and operational, including Xuber Enterprise server and Xuber Messaging server.

Requirement

Messaging Service

Xuber Messaging must be running and configured to handle event messages. The messaging service is the transport mechanism for integration.

GLOBAL XLPro Requirements

Version

XLPro Version 2.8.30

GLOBAL XLPro must be running version 2.8.30 or compatible. Earlier or later versions may not be compatible with the integration.

Requirement

Database Access

The XLPro database server must be accessible from the Xuber environment. Network connectivity between the systems is essential.

Database Requirements

SQL Server

GLOBAL XLPro Database

A Microsoft SQL Server instance with XLPro database installed. Server must support the SQL Server Integration Services (SSIS) and Distributed Transaction Coordinator (MSDTC).

Features: SQL Agent, Integration Services, MSDTC enabled

Credentials

Database Access

Database accounts must have appropriate permissions to read from and write to the XLPro database. DBO ownership or equivalent database role required.

⚠️
Verify Compatibility

Before starting deployment, confirm that your GLOBAL XLPro version and SQL Server version are compatible with the XLPro integration release you are deploying. Version mismatches can cause installation failures or runtime errors.

Architecture

Integration Architecture

Understanding the complete architecture and how components connect

The XLPro integration architecture spans multiple servers and systems. Understanding how these components connect helps you troubleshoot issues and plan deployments effectively.

System Architecture

Xuber Environment
• Xuber Enterprise Server - Creates and manages policies, claims, and business events
• Xuber Messaging Server - Broadcasts events to listening services
• XLPro Integration Components - Listen for events and prepare data for XLPro
XLPro Environment
• GLOBAL XLPro Application - Reinsurance and policy management
• XLPro Database Server - Stores policy, claims, and financial data
• USM 6-9 Load Service - Processes incoming messages from Xuber

Message Flow Sequence

Step 1: Event Creation

Underwriter creates a new policy in Xuber Enterprise. The policy data is stored in the Xuber database.

Step 2: Event Broadcasting

Xuber Messaging publishes a "Policy Created" event to all registered listeners, including XLPro Integration.

Step 3: Data Capture

XLPro Integration listener receives the event, extracts policy details, and formats the data for XLPro.

Step 4: Transmission

Formatted message is sent to the XLPro database via a secure connection. If the connection fails, the message queues.

Step 5: Processing

USM 6-9 Load service on the XLPro database server receives and processes the message.

Step 6: Completion

Data is loaded into XLPro database tables. The policy is now visible in both Xuber and GLOBAL XLPro.

Key Architecture Points

Loose Coupling

Xuber Enterprise does not wait for XLPro confirmation. It completes the policy transaction immediately. XLPro integration happens asynchronously in the background.

Message Queuing

If XLPro is temporarily offline, messages queue on Xuber Messaging. When XLPro is back online, queued messages process automatically in order.

Reliability

No data is lost. The integration uses persistent message queues and database transactions to ensure guaranteed delivery and processing.
