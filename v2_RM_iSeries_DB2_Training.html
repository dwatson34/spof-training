iSeries Platform Overview

What iSeries is and how Genius and Xuber depend on it

iSeries, also called AS400 or IBM i, is the enterprise platform running the Genius insurance core system. Xuber's API communicates with Genius on iSeries through an integration layer. iSeries availability equals Xuber availability.

Architecture position

Xuber HTMLUI - Angular on EC2
Xuber .NET API Layer on EC2
iSeries Integration Server on EC2
IBM iSeries - AS400 - Genius core
DB2 for i - Genius database
LPAR

Logical Partition

A separate virtual iSeries within the physical hardware. Each Genius environment runs in its own LPAR.

Library

Like a folder

iSeries organises objects in libraries. Each Genius environment has its own library list.

Job

Running process

Every program execution is a job. Job logs record what happened. The joblog is your first diagnostic tool.

PTF

Program Temporary Fix

IBM's patch mechanism. PTFs are cumulative bundles of fixes. Applying PTFs is a core RM task.

Green screen: iSeries is managed via a 5250 terminal interface. IBM ACS - Access Client Solutions - is the standard tool at DXC.

Concept 2

Essential AS400 Commands

The commands you will use every day for iSeries operations

iSeries is operated by typing CL - Control Language - commands. These 10 commands cover 90 percent of daily RM operations. All follow the verb-noun pattern.

WRKACTJOBWork with Active Jobs. Shows all currently running jobs. Use to find stuck jobs and check CPU usage. Press F11 to add the CPU percent column.
WRKSYSSTSWork with System Status. Shows overall health including CPU percent and ASP disk usage. First thing to check on a performance call.
DSPJOBLOGDisplay Job Log. Shows all messages from a job. Read from the bottom up. The last CPF error message tells you what failed and why.
WRKLIBWork with Libraries. Filter by name: WRKLIB LIB(GENIUS*) to see all Genius environment libraries. Essential for environment administration.
SAVLIB / RSTLIBSave and Restore Library. Creates a backup of a Genius library to a save file. Always run SAVLIB before a PTF install so you can restore if it fails.
STRSBS / ENDSBSStart and End Subsystem. Controls Genius subsystems. STRSBS GENIUSUAT starts the UAT subsystem. Always confirm with the client before ending a production subsystem.
WRKOBJWork with Objects. Find any object by name and type. WRKOBJ OBJ(*ALL/OBJECT) OBJTYPE(*PGM) finds all programs named OBJECT.
GRTOBJAUTGrant Object Authority. Used to fix authority failures during PTF installations. Always log what authority was granted and why.
ADDLIBLEAdd Library List Entry. Adds a library to the current job's library list. Used when a PTF build fails because an object is not found.
GO MAINNavigate to the main menu from anywhere. F3 exits, F12 cancels, F1 is help. These work on every green screen.

DB2 for i Administration

Querying, monitoring and maintaining the Genius database

DB2 for i is the integrated database on iSeries. Genius data lives here. The RM team must be able to query it, back it up, check storage health and restore it for environment refreshes.

Useful diagnostic SQL via ACSSQL
-- Check active connections to Genius DB
SELECT JOB_NAME, USER_NAME,
  CONNECTION_COUNT
FROM QSYS2.ACTIVE_JOB_INFO
WHERE JOB_TYPE = 'I';

-- Find record locks
SELECT * FROM
  QSYS2.RECORD_LOCK_INFO
WHERE TABLE_SCHEMA
  = 'GENIUSPRD';

-- Check ASP disk usage
SELECT
  ROUND(TOTAL_SIZE/1073741824,1)
    AS SIZE_GB,
  ROUND(USED_SIZE/1073741824,1)
    AS USED_GB
FROM QSYS2.ASP_INFO;

DB2 health checks

Journals

Journal receivers must be attached

Genius requires journalling for commitment control. If a journal receiver detaches or fills, Genius stops. Check daily.

ASP usage

Keep below 80 percent

iSeries performance degrades above 80 percent ASP usage. Alert the team at 70 percent to allow time to act.

Locks

Record locks cause user errors

If a Genius user gets Record in use errors, use RECORD_LOCK_INFO to find the locking job and end it safely.

IBM ACS recommended: Use Access Client Solutions from your Windows workstation for all SQL work. It has syntax highlighting and query history.

Concept 4

Creating a Genius Environment

Step-by-step: building a new Genius environment on iSeries

Creating a new Genius environment for dev, test or UAT requires creating libraries, copying objects, configuring journals and setting up subsystems. Strict sequencing is essential.

1

Create target libraries

CRTLIB LIB(GENIUSUAT) creates the main application library. Repeat for GENISUATD (data) and GENISUATWRK (work files).

2

Copy objects from source environment

CPYLIB FROMLIB(GENIUSPROD) TOLIB(GENIUSUAT) copies all programs and files. This can take 30 to 60 minutes for a full copy.

3

Apply environment configuration

Update the Genius system tables GNSCONFIG and GNSSYSPARM with the new environment name, library list and connection strings.

4

Set up journals

CRTJRN JRN(GENIUSUAT/GENISJRN) creates the journal. STRJRNPF starts journalling on all physical files in the new library.

5

Create subsystem

CPYSBSD FROMSBSD(GENIUSPRD) TOSBSD(GENISUATS) copies the subsystem. Update routing entries to point to the new environment libraries.

6

Test and verify

STRSBS GENISUATS starts the subsystem. Log in via ACS and verify Genius reaches its opening menu. Check WRKACTJOB for subsystem jobs.

Library list matters: Each environment must have its own library list. Mixing library lists causes data from one environment to appear in another - a serious data integrity risk.

Concept 5

Resolving PTF Build Issues

Reading joblogs, diagnosing failures and applying fixes for Genius PTF installations

PTF installation is how Genius software updates are applied. When it fails, the joblog is your primary diagnostic tool. Learn to read it from bottom to top.

Diagnosis steps

1

Find the failed job

In WRKACTJOB or WRKSPLF, find the PTF build job. It shows CPF status (complete with errors) or END (ended abnormally).

2

Open the joblog

Select the job, Option 10 Display job log, or DSPJOBLOG. Press F18 to jump to the bottom and work backwards looking for CPF messages.

3

Identify the CPF error

Note the CPF message ID. Place cursor on it and press F1 for help text explaining the error and suggested fix.

4

Apply fix and retry

Common fixes: end conflicting jobs, grant authority with GRTOBJAUT, add missing library with ADDLIBLE, restart the subsystem.

Common CPF error codes

CPF9801

Object not found

The PTF references an object that does not exist. Check the library list. Run CHKPRDOPT to verify prerequisites are installed.

CPF3702

Object in use

A job has the target object locked. Run WRKOBJ, Option 14 to see locks. End the locking job, then retry.

CPF2110

Library not found

Target library does not exist or is not on the library list. Verify with WRKLIB and use ADDLIBLE to add it.

CPF0001

Generic error

Look at previous messages in the joblog for the actual cause. CPF0001 just indicates a command failed, not why.
