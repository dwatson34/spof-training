Azure DevOps Pipeline Overview

How Xuber CI/CD is structured and where the RM team fits in the deployment process

Xuber uses Azure DevOps for all CI/CD pipeline automation. The RM team manages the QA and production deployment stages which require manual approval before they run.

Xuber pipeline stages

1. CI - Build and Unit Tests - automatic on merge
2. Deploy to DEV - automatic
3. Deploy to QA - RM approval gate
4. SmartTest regression - automatic after QA deploy
5. UAT sign-off - BA approval gate
6. Deploy to PROD - RM and Manager approval
RM responsibility

Stages 3 and 6

RM team approves and monitors the QA deployment at Stage 3 and co-approves the Production deployment at Stage 6. RM also owns SmartTest result review.

Pipeline location: Azure DevOps, Xuber project, Pipelines, xuber-main-pipeline. Bookmark this - you will use it every deployment cycle.
Approval notifications: The RM team lead receives an email when Stage 3 needs approval. No action within 24 hours causes the pipeline to time out and the deployment to be abandoned.

Concept 2

QA Environment Deployment

Approving, monitoring and verifying the Xuber QA deployment

When a deployment reaches Stage 3, the RM team must review the change list, approve the deployment, monitor it to completion and confirm QA is healthy before SmartTest runs.

1

Review the deployment request

Check the email notification. Click the Azure DevOps link. Review which tickets are included, who raised it, and the release notes in the PR description.

2

Confirm DEV is stable

Stage 2 (DEV deploy) must be green before approving QA. Click Stage 2 in the pipeline to confirm it passed and DEV smoke tests succeeded.

3

Approve the deployment

Click Approve in Azure DevOps. Add a comment: Approved by [name] - DEV confirmed stable. The pipeline starts Stage 3 automatically.

4

Monitor progress

Watch the pipeline in real time. Each task shows a green tick or red cross. Deployment takes approximately 15 minutes. If a task fails, click it to see the log.

5

Verify QA is healthy

Navigate to the QA Xuber URL. Confirm the login page loads. Check CloudWatch for EC2 or ALB errors. Post the all-clear in the Teams deployment channel.

Concept 3

Reading Pipeline YAML

Understanding the YAML that defines Xuber deployment stages

Xuber pipelines are defined in azure-pipelines.yml in the Git repository. You do not need to write YAML from scratch but you must be able to read it to understand what a failing stage is trying to do.

azure-pipelines.yml - QA stageYAML
stages:
  - stage: DeployQA
    displayName: 'Deploy to QA'
    dependsOn: DeployDev
    condition: succeeded()
    jobs:
      - deployment: QADeploy
        environment:
          'xuber-qa'
        strategy:
          runOnce:
            deploy:
              steps:
              - task:
                  AzureWebApp@1
                inputs:
                  appName:
                    'xuber-qa-app'
              - task:
                  SqlAzureDacpac@1
                inputs:
                  ServerName:
                    '$(QA_DB_SERVER)'
stages

Top-level groups

Each stage runs after the previous. dependsOn and condition control whether a stage runs at all. If DeployDev fails, DeployQA is skipped.

jobs

Units of work

A job runs on an agent. Deployment jobs have environments and approval gates. Each job logs its output independently.

steps

Individual tasks

Each task does one thing. A failed task shows in red. Click it to see the full log including the exact error message.

$(VAR_NAME)

Variables

Server names and connection strings are stored as pipeline variables or Azure Key Vault secrets, never in the YAML file itself.

Concept 4

SmartTest Regression

Running the Genius PTF regression suite and interpreting results

SmartTest is the automated regression testing tool for Genius. It replays recorded user transactions against the application and compares results character-by-character to a known-good baseline. Any difference is flagged for human review.

Running SmartTest

1

Confirm QA is stable

Check WRKACTJOB on the QA iSeries. Genius QA login must work before SmartTest can run.

2

Open SmartTest Manager

RDP to the QA EC2 server. Open C:\SmartTest\STManager.exe. Select Suite: XuberRegressionFull. Click Run All.

3

Monitor progress

Full suite of approximately 120 scripts takes 25 minutes. Do not log into Genius manually during the run - it causes timing failures.

4

Review the HTML report

Report generates at C:\SmartTest\Reports\[date-time]\index.html. Green equals pass. Red equals fail. Click any failure to see the diff screenshot.

Failure classification

False positive - can proceed

Environment noise

Date or time value changed on screen. Sequential reference number incremented. Timing issue that passes on retry. Cosmetic text change.

Genuine regression - escalate

Real defect

Error message appeared where none before. Calculated premium or reserve is wrong. Workflow went to wrong screen. Multiple related scripts failed.

Pass threshold: 95 percent pass rate required before approving Stage 5. Any failure in a financial workflow (payment, reserve) must be investigated regardless of percentage.
