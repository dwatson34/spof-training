Xuber Codebase Tour

Where to find everything in the Xuber HTMLUI repository

The Xuber HTMLUI follows a standard Angular feature-based structure. Knowing where things live saves hours of searching when debugging or adding features.

Repository structureStructure
xuber-htmlui/
  src/
    app/
      core/
        auth/           // JWT, guards
        interceptors/   // auth, logging
        layout/         // shell, nav
      shared/
        components/     // buttons, cards
        pipes/          // currency, date
        directives/
      features/
        policy/
          components/
          services/     // api + facade
          models/       // TS interfaces
        claims/
        lmm/
    environments/
      environment.ts
      environment.prod.ts
    proxy.conf.json     // local API proxy
  angular.json
  tsconfig.json
core/

App-wide singletons

AuthService, HttpInterceptors, the shell layout. Should only be imported in AppModule, never in feature modules.

shared/

Reusable UI

Components, pipes and directives used across multiple features. SharedModule exports these for feature modules to import.

features/

Business domains

Each business domain is self-contained: components, services, models and routing in its own folder.

environments/

API configuration

environment.ts for local dev with proxy. environment.prod.ts for production with full URLs. The Angular build swaps these automatically.

Local Development Setup

Running the Xuber HTMLUI locally with the API proxy

The Xuber HTMLUI requires the API proxy to be active for local development. Without it, all API calls fail with CORS errors.

Getting startedShell
# Clone and install
git clone [xuber-htmlui-repo]
cd xuber-htmlui
npm install

# Start with API proxy
ng serve --proxy-config
  proxy.conf.json

# Opens at http://localhost:4200
# API calls to /api/* are
# proxied to UAT backend
proxy.conf.jsonJSON
{
  "/api": {
    "target":
      "https://uat.xuber-internal",
    "changeOrigin": true,
    "secure": false
  }
}
CORS error in console?

Proxy is not running

If you see a CORS error, you started ng serve without the proxy flag. Stop and restart with --proxy-config proxy.conf.json.

401 on all API calls?

Not authenticated

Log in at localhost:4200/login first. The proxy forwards your credentials to the UAT backend. Check the JWT token exists in memory.

Node version

Use the LTS version

The Xuber HTMLUI requires Node 18 LTS or above. Use nvm to switch versions: nvm use 18.

Environment files

Never commit secrets

environment.prod.ts is not committed to git. It is injected by the Azure Pipeline build using pipeline variables.

Git Workflow and Code Standards

Branching strategy, PR process and commit conventions

The Xuber HTMLUI uses a trunk-based development workflow. All developers work in short-lived feature branches and merge to main frequently. Long-lived branches cause merge conflicts and are discouraged.

Git workflowShell
# Create a branch from main
git checkout main
git pull origin main
git checkout -b feat/XUB-1234-
  policy-search-filter

# Commit with ticket reference
git commit -m   "feat(policy): add status
   filter to policy list

   XUB-1234"

# Push and raise PR to main
git push origin feat/...

# After PR approval and merge,
# delete the feature branch
Commit format

Conventional commits

type(scope): description. Types: feat, fix, refactor, test, docs, chore. The Jira ticket reference goes in the commit body.

PR standards

Review requirements

All PRs need at least 1 approving review. No changes to the main branch without a PR. The reviewer checks: TypeScript types, test coverage, no-explicit-any, and follows the two-service pattern.

Branch naming

feat/ or fix/ prefix

feat/XUB-1234-brief-description for features. fix/XUB-5678-brief-description for bug fixes. The Jira ticket ID links the branch to the work item.
