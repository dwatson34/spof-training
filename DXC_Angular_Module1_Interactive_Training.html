Core Concept 1

What is Angular?

A TypeScript-based framework for building scalable Single-Page Applications — and the technology powering the Xuber HTMLUI.

Angular is an open-source front-end framework maintained by Google. Unlike a library, Angular is a full framework — it provides routing, forms, HTTP, testing, and a component model out of the box. In Xuber, it is the entire browser-facing layer.

Four defining characteristics

⚙️ Component-Based

The UI is broken into self-contained, reusable components. Each has its own HTML, CSS, and TypeScript. Example: PolicyHeaderComponent, ClaimsGridComponent.

🔷 TypeScript First

Designed for TypeScript — strong typing, interfaces, decorators, and IntelliSense. Xuber benefits from type-safe API calls across the codebase.

📦 NgModules

Related components and services are grouped into modules. This keeps large apps like Xuber organised and allows features to load lazily.

🔗 Two-Way Binding

Changes in the TypeScript class update the view, and user input updates the class. Eliminates manual DOM manipulation for form-heavy Xuber screens.

Where Angular fits in Xuber

Core Concept 2

Components

The fundamental building block of every Angular application — Template + Class + Styles.

Think of a component as a reusable UI brick. A PolicyHeaderComponent, a ClaimsListComponent, a NavigationBarComponent — each is self-contained with its own appearance and behaviour.

Anatomy of a component

policy-header.component.tsTypeScript
import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-policy-header',
  templateUrl: './policy-header.component.html',
  styleUrls: ['./policy-header.component.css']
})
export class PolicyHeaderComponent {
  @Input() policyNumber: string = '';
  @Input() status: string = 'Active';
}
Using the component in a parent templateHTML
<app-policy-header
  [policyNumber]="selectedPolicy.ref"
  [status]="selectedPolicy.status">
</app-policy-header>

Key concepts

@Component

Decorator

Marks a class as a component and attaches its metadata — the selector (HTML tag name), template, and stylesheet.

selector

HTML Tag

selector: 'app-policy-header' means you embed it as <app-policy-header> anywhere in a parent template.

@Input()

Receiving Data

Marks a property as an input — a parent passes data in via property binding. This is the primary way to pass data down the component tree.

CLI

4 Files Generated

ng generate component policy-header creates .ts, .html, .css, and .spec.ts automatically and registers the component.

Core Concept 3

NgModules

Organising components, directives, and services into cohesive units and controlling their visibility.

Every Angular app has at least one module — AppModule. Modules declare which components belong to them, import external functionality, and export components for use elsewhere.

Module structure in Xuber

AppModule (Root)
PolicyModule
ClaimsModule
LmmModule
SharedModule
Each feature module is lazy-loaded on navigation — keeping the initial bundle small.
Golden rule: A component must be declared in exactly ONE module. To use it elsewhere, export it from its module and import that module wherever needed.

The @NgModule decorator

policy.module.tsTypeScript
@NgModule({
  // Components this module owns
  declarations: [
    PolicyListComponent,
    PolicyDetailComponent
  ],
  // External modules needed
  imports: [
    CommonModule,
    HttpClientModule,
    ReactiveFormsModule
  ],
  // What other modules can use
  exports: [PolicyListComponent]
})
export class PolicyModule {}

Core Concept 4

Data Binding

Connecting your TypeScript class to your HTML template — four binding types, each with a different direction and purpose.

Data binding is how Angular keeps the UI and TypeScript class in sync. Understanding the four types — and when to use each — is fundamental to writing Angular templates.

InterpolationClass → Template
{{ value }}
Renders the value of a class property as text. Read-only — the DOM cannot update the class this way.
<p>Policy: {{ policyNumber }}</p>
Property BindingClass → DOM
[property]="expression"
Dynamically sets a DOM element's property from a TypeScript expression. Use square brackets.
<input [disabled]="isReadOnly"> <button [disabled]="isSaving">Save</button>
Event BindingDOM → Class
(event)="handler()"
Listens for a DOM event and calls a TypeScript method when it fires. Use parentheses.
<button (click)="savePolicy()">Save</button>
Two-Way BindingClass ↔ DOM
[(ngModel)]="property"
Combines property and event binding. Changes in the class update the input; typing updates the class. Requires FormsModule.
<input [(ngModel)]="policyRef"> <!-- "banana in a box" -->
💡
Memory aid: "banana in a box"

[(ngModel)] — the parentheses (banana) sit inside the square brackets (box). This is how Angular developers remember two-way binding syntax.

Core Concept 5

Services & Dependency Injection

Sharing logic and data cleanly across the application — without tangling business logic inside components.

A Service is a TypeScript class annotated with @Injectable that contains business logic, HTTP calls, or shared state. Angular's DI system provides an instance to any component that requests it — you never call new PolicyService() yourself.

Creating and injecting a service

policy.service.tsTypeScript
@Injectable({ providedIn: 'root' })
export class PolicyService {

  constructor(private http: HttpClient) {}

  getPolicies() {
    return this.http.get<Policy[]>(
      '/api/v2/policies'
    );
  }
}
policy-list.component.tsTypeScript
export class PolicyListComponent {
  policies: Policy[] = [];

  // Angular injects PolicyService here
  constructor(private svc: PolicyService) {}

  ngOnInit() {
    this.svc.getPolicies()
      .subscribe(p => this.policies = p);
  }
}

Core Concept 6

Angular Router

Navigation without page reloads — mapping URL paths to components and protecting routes with Guards.

The Angular Router maps URL paths to components, enabling navigation within Xuber without full page reloads. Route Guards protect pages — for example, requiring authentication before accessing Claims.

Xuber route configuration

PathComponent
/policiesPolicyListComponent
/policies/:idPolicyDetailComponent
/claimsClaimsListComponent
/claims/:id/paymentsPaymentsComponent
**NotFoundComponent
Programmatic navigationTypeScript
// Navigate from TypeScript:
this.router.navigate([
  '/policies', policyId
]);

Route Guards

CanActivate
Runs before navigating to a route. Return true to allow, false to block. Use for auth checks on Xuber policy/claims pages.
CanDeactivate
Runs when leaving a route. Warn users if they have unsaved changes on a Xuber policy edit form.
Resolve
Pre-fetches data before a route activates. The component receives ready data — no loading spinner needed.

Core Concept 7

HttpClient & RxJS Observables

Consuming the Xuber REST API from Angular — asynchronous data without blocking the UI.

Angular's HttpClient returns RxJS Observables. Components subscribe to receive data asynchronously — critical for calling Xuber API endpoints (Policies, Claims, LMM) without freezing the browser.

Request flow
User action
→
Component calls service
→
HttpClient.get()
→
Xuber REST API
→
Observable emits
→
View updates
policy.service.ts + componentTypeScript
// Service
getPolicy(id: number): Observable<Policy> {
  return this.http.get<Policy>(
    `/api/policies/${id}`
  );
}

// Component ngOnInit
this.policyService
  .getPolicy(this.policyId)
  .subscribe(p => { this.policy = p; });

Useful RxJS operators

map()Transform the response — extract .data from a wrapper object.
catchError()Handle API errors gracefully — return a fallback Observable instead of crashing.
switchMap()Cancel the previous HTTP call when a new one starts — essential for search-as-you-type.
takeUntil()Auto-unsubscribe when the component is destroyed — prevents memory leaks.
debounceTime()Wait for the user to stop typing before making an API call.
Tip: In templates, prefer the async pipe:
{{ policies$ | async }}
It handles unsubscription automatically.
