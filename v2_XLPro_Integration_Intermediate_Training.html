XLPro Integration Installation & Configuration

Step-by-step procedures for deploying XLPro integration - For developers and technical architects planning and executing deployments

⚠️
Intermediate Level

This module provides technical installation and configuration procedures. You should be familiar with database administration, SQL Server, and network configuration. Hands-on experience required.

Pre-Installation

Verification checklist, environment preparation, and security setup before installing integration components.

Phase 2

Database Setup

Preparing both XLPro and Xuber databases with schema updates, scripts, and permissions configuration.

Installation

Running the XLPro integration and USM Load installers on the appropriate servers with correct configuration.

Phase 4

Configuration

Configuring integration parameters, messaging queues, database connections, and service accounts.

Phase 1

Pre-Installation: Preparation

Verify your environment and prepare for deployment

Before you deploy XLPro integration, verify that your environment meets all requirements and that you have the necessary permissions, access, and files. This phase prevents installation failures and ensures smooth deployment.

Pre-Installation Checklist

1

Verify Version Compatibility

Confirm GLOBAL XLPro is version 2.8.30. Confirm SQL Server is 2014 or later with Integration Services enabled. Verify Xuber Enterprise version matches XLPro integration release notes.

2

Obtain Installation Media

Download the XLPro integration release package from your software repository. Verify the package includes: XuberXLProIntegration.exe, Setup_XLProIntegration_XuberHTML5.exe, and AnswerFile.config.

3

Prepare Network Access

Confirm network connectivity from Xuber servers to XLPro database server. Test firewall rules for SQL Server port 1433 (or custom port). Verify DNS resolution between systems.

4

Prepare Service Accounts

Create Windows service accounts for XLPro integration components with appropriate permissions. These accounts need SQL Server database read/write access and file system permissions.

5

Backup Databases

Critical: Back up both the XLPro database and Xuber Enterprise database before beginning installation. Database schema modifications cannot be easily reversed.

6

Verify Admin Access

Confirm you have administrator rights on all servers where installation will occur. SQL Server DBA permissions required to execute database scripts and modify schemas.

⚠️
Database Backup Required

Do not proceed to database setup without verified backups of both XLPro and Xuber databases. If installation fails and databases are corrupted, you must restore from backup.

Phase 2

Database Preparation

Update database schemas and configure permissions

The XLPro integration requires database schema updates on both the GLOBAL XLPro database and the Xuber Enterprise database. These changes create tables, stored procedures, and views needed for the integration to function.

Step 1: Prepare GLOBAL XLPro Database

A

Extract Integration Scripts

Extract the XLPro integration package to a temporary folder. Locate the SQL scripts in the /xlpro.integration-X.X.XXX/scripts/ folder.

B

Launch SQL Server Management Studio

Open SQL Server Management Studio. Connect to the XLPro database server using a database administrator account.

C

Execute XLPro Schema Script

Open File → Open → File browser → Select Xuber.XLProIntegration.XLProDatabase.sql. Review the script and click Execute. This updates the XLPro database with required schema changes.

D

Verify Schema Creation

In the Object Explorer, navigate to XLPro database → Tables. You should see new tables prefixed with xlpro_* (e.g., xlpro_messages, xlpro_staging, xlpro_log). If tables do not appear, the script execution failed.

Step 2: Prepare Xuber Enterprise Database

A

Connect to Xuber Database

In SQL Server Management Studio, connect to the Xuber Enterprise database server. You may need to create a new connection to a different server.

B

Execute Xuber Schema Script

Open File → Open → Select Xuber.XLProIntegration.XuberDatabase.sql. Review and execute the script. This adds event publishing hooks to the Xuber database.

C

Verify Schema Changes

Navigate to Xuber database → Tables. New tables and stored procedures should be visible. Verify that xlpro_event_subscriptions table exists and is empty.

Execution Time: Database script execution typically takes 2-5 minutes depending on database size. Monitor SQL Server Agent jobs during execution. If any errors appear in the Messages tab, do not proceed to installation.

Phase 3

XLPro Integration Installation

Running the installation on Xuber servers

The XLPro integration installer deploys components to Xuber Enterprise and Xuber Messaging servers. The installer is package-based and configurable, allowing you to select which components to install on each server.

Installation Steps

1

Right-Click and Run As Administrator

On the Xuber Enterprise server, locate XuberXLProIntegration.exe. Right-click the file and select Run as administrator. The installer requires elevated privileges.

2

Select Answer File

On the first installer page, click the folder icon to browse and select AnswerFile.config. This file contains your environment-specific configuration including server names, database connections, and service accounts.

3

Review Installation Path

Verify the installation folder (typically C:\Program Files (x86)\DXC\). If you want to change it, click the browse button and select a different location. Click Next.

4

Select Packages to Install

The second page displays available packages. Check the packages for your deployment:

  • ✓ XLPRO INTEGRATION CORE SERVICES - Always required
  • ✓ XLPRO INTEGRATION DESIGN STUDIO - If Design Studio is deployed on this server
  • ✓ XLPRO INTEGRATION MESSAGING CUSTOM MODULES - If Xuber Messaging is on this server

5

Monitor Installation Progress

The installer displays a progress bar while extracting and installing components. Do not close the installer window. Installation typically takes 3-5 minutes.

6

Verify Completion

When the installer displays "Operation complete", click Finish. The installation is complete on this server. If Xuber Messaging is on a different server, run the installer there as well.

✓
Multi-Server Deployment

If Xuber Enterprise and Xuber Messaging are on different servers, run the installer on both servers with the same AnswerFile.config. The integration components register and communicate across servers.

Phase 4

Configuration & Integration Setup

Configuring integration parameters and messaging connections

After installation, the integration must be configured with connection strings, messaging parameters, and service account permissions. Configuration files are created during installation and must be reviewed and customized for your environment.

Configuration File Locations

Xuber Server

C:\Program Files (x86)\DXC\Xuber XLPro Integration\config\

Contains integration configuration for Xuber side components including messaging subscriptions and database connections.

XLPro Server

C:\Program Files (x86)\DXC\XLPro Integration Load\config\

Contains configuration for the USM 6-9 Load service that processes messages on the XLPro side.

Key Configuration Tasks

1

Verify Connection Strings

In each config folder, open connectionstrings.config. Verify that database server names, port numbers, and credentials are correct for your environment. Test connections using SQL Server Management Studio to confirm.

2

Configure Messaging Subscriptions

Open messagingconfig.xml. Configure which Xuber events trigger integration messages. By default, Policy, Claim, and Financial events are subscribed. Customize based on your business requirements.

3

Set Service Account Permissions

Grant the service account read/write permissions to the integration installation folder. SQL Server Login permissions must include SELECT, INSERT, UPDATE on integration tables in both databases.

4

Start Integration Services

Open Services (services.msc) and verify that "DXC XLPro Integration" service is present and set to Automatic startup. Start the service. Check that the service runs without errors in Event Viewer.

5

Enable Logging

In loggingconfig.xml, set LogLevel to DEBUG. Specify a log file location with write permissions. Logging helps troubleshoot integration issues during testing and go-live.

Testing Connections: After configuration, test each database connection from both servers using SQL Query Analyzer with the same credentials the service will use. This prevents authentication failures at runtime.

Phase 5

Testing & Validation

Verifying that integration is functioning correctly

Before moving to production, validate that the integration is functioning. Test message flow, database synchronization, and error handling to ensure reliability.

Validation Procedures

1

Verify Service Status

On both Xuber and XLPro servers, open Services and confirm all XLPro integration services are running with status "Started". Check Event Viewer for any service startup errors.

2

Create Test Data in Xuber

In Xuber Enterprise, create a test policy. Use a recognizable test reference (e.g., "INTEGRATION-TEST-001"). Save the policy and note the creation time.

3

Monitor Message Flow

On the Xuber server, open the integration logs. Look for messages indicating that the test policy event was captured and sent to XLPro. If logs show errors, review and fix configuration issues.

4

Verify Data in XLPro Database

On the XLPro database server, open SQL Server Management Studio. Query the xlpro_staging table:

SELECT * FROM xlpro_staging
WHERE policy_ref LIKE '%INTEGRATION-TEST%'
ORDER BY created_date DESC
The test policy should appear in staging within 30-60 seconds of creation.

5

Verify Load Processing

Check xlpro_messages and xlpro_log tables to confirm that messages are being processed by the USM Load service. If messages remain in staging longer than 5 minutes, there may be a processing issue.

6

Test Error Handling

Temporarily stop the integration service on one server and create another test policy. Verify that messages queue. Restart the service and confirm queued messages process automatically.

✓ Ready for Production

All tests pass, message flow works, no errors in logs, data synchronizes within expected time.

✗ Not Ready Yet

Tests fail, messages don't flow, data doesn't appear in XLPro, or errors appear in event logs.

Go-Live Readiness: Before production deployment, run validation tests with production-like data volumes and transaction rates. Monitor system performance during testing to identify any bottlenecks or resource constraints.
