Step-by-Step Installation Process

Phase 1: Database Preparation (Pre-Installation)

Step 1.1: Extract xlpro.integration-X.X.XXX.zip from installation media Step 1.2: Back up GLOBAL XLPro database Step 1.3: Back up Xuber Enterprise database Step 1.4: Launch SQL Server Management Studio Step 1.5: Run Xuber.XLProIntegration.XLProDatabase.sql script Step 1.6: Run Xuber.XLProIntegration.XuberDatabase.sql script
⚠️ Critical: Never skip database backups. If the SQL scripts fail, you may need to restore.

What these scripts do:

  • Create XLPro Integration tables and views
  • Add configuration data for message routing
  • Set up stored procedures for data transformation

Phase 2: XLPro Integration Service Installation

Running the Main Installer

1. Right-click XuberXLProIntegration.exe → Run as administrator 2. Select answer file (AnswerFile.config) 3. Choose packages to install: - On Xuber Enterprise server: Core + Schedulers modules - On Xuber Messaging server: Messaging modules - On Design Studio machines: Design Studio modules 4. Enter service account credentials when prompted 5. Review installation path 6. Click Install
Answer File: The AnswerFile.config contains installation settings (server names, database paths, service accounts). This automates the installation process — no wizard prompts needed if the answer file is correct.

Service Accounts: Integration services run under dedicated accounts with limited permissions. This is safer than admin accounts.

Phase 3: USM 6-9 Load Setup on XLPro Server

This component processes incoming messages into GLOBAL XLPro

  1. Extract USMDeploy.zip on the XLPro database server
  2. Create staging database (e.g., USMStaging)
  3. Run ACORD_RI_USM.sql script against staging database
  4. Create SQL Server login (e.g., XLProUSM) with db_owner rights
  5. Create folder structure: XLPro_USM with subfolders (Archive, In, Staging_Logs, Preimport_Logs)
  6. Edit configuration files (.dtsConfig) with correct paths and connection strings
  7. Create SQL Agent jobs to schedule SSIS packages
⚠️ Important: Folder paths in config files must match exactly. A typo in a path will cause the SSIS package to fail silently.

Configuration Files (.dtsConfig)

Two key configuration files control SSIS package behavior:

1. USM2Staging.dtsConfig — Moves data from Xuber to staging database

Key settings: - Data Source: localhost (or server name for staging database) - uid: XLProUSM (the SQL login created earlier) - Initial Catalog: USMStaging - Password: (password for XLProUSM login) - ArchivePath: C:\XLPro_USM\Archive - InPath: C:\XLPro_USM\In - LogPath: C:\XLPro_USM\Staging_Logs

2. Staging2XLPro.dtsConfig — Moves validated data from staging to XLPro

Key settings: - Similar connection string to XLPro database - LogPath: C:\XLPro_USM\Preimport_Logs - Password for XLProUSM login
Pro Tip: Edit config files in Notepad running as Administrator. Search for specific XML elements to find the settings you need to update.

SSIS Packages and SQL Agent Jobs

SSIS packages are automated jobs that run on a schedule

Package Purpose Typical Frequency
USM2Staging.dtsx Extract data from Xuber, validate, load to staging Every 15 minutes
Staging2XLPro.dtsx Move validated data from staging to XLPro Every 30 minutes

Creating SQL Agent Jobs:

  1. Open SQL Server Management Studio
  2. Go to SQL Server Agent → Jobs → New Job
  3. Set job name (e.g., "XLPro USM to Staging")
  4. Create step using SSIS Integration Services type
  5. Point to the .dtsx package file
  6. Set schedule (15 min, 30 min, hourly, etc.)
  7. Set run as account (service account created earlier)
⚠️ Timing: Stagingpackage should run AFTER USM2Staging completes. Stagger the schedules (USM2Staging at :00 and :15, Staging2XLPro at :10 and :30).

Production vs. UAT Environments

XLPro Integration runs in multiple environments

Component Production UAT QA/Dev
Xuber Enterprise Full production setup Mirrors production Minimal setup
GLOBAL XLPro Full production setup Mirrors production Sometimes present
Integration frequency Every 15-30 min (automated) Every 30-60 min or manual Manual/on-demand
SharePoint Dedicated production Shared with production Often absent
UAT Challenge: In UAT, SharePoint sites may be created/deleted on the Production server to save space. This means you're testing with shared infrastructure — document changes in UAT could affect production SharePoint.

Manual Steps in UAT: LORS file transfer, document scanning, and some message processing may be manual instead of automated.

Troubleshooting & Common Issues

Issue 1: SSIS Package Fails to Run

Cause: Config file paths are incorrect Solution: Verify folder paths exist Check config file for typos Ensure folders have read/write permissions Restart SQL Agent after config changes

Issue 2: Data Not Appearing in XLPro

Cause: Staging database not receiving data Solution: Check Xuber messaging logs Verify SSIS job ran successfully Check staging database for data Review error logs in Staging_Logs folder

Issue 3: "Cannot Connect to Database" Error

Cause: SQL login credentials incorrect or user blocked Solution: Verify XLProUSM login exists Check password in config file Ensure login has db_owner on both databases Check firewall allows connection to database server

Issue 4: SSIS Job Runs But No Logs

Cause: Log file paths don't exist Solution: Create all required folders Verify folder names match config file Grant permissions to service account Check disk space on log drive
